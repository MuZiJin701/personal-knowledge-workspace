# Domain Docs

本工作区包含多个独立知识主题，领域文档采用按需维护的多上下文约定。

`GLOSSARY-MAP.md` 是当前布局的入口；已有地图决定读取路径，主题数量本身不要求创建更多术语文件。

## 阅读顺序

1. 从根目录 `GLOSSARY-MAP.md` 定位与当前任务相关的上下文。
2. 阅读该上下文的 `GLOSSARY.md`，并使用其中定义的规范术语。
3. 阅读主题目录中与当前问题相关的知识文档。
4. 如果存在相关 ADR，再读取其约束和背景；检查根目录 `docs/adr/` 和相关主题的 `docs/adr/`。

地图未登记相关上下文或文件不存在时静默继续；只有稳定术语或真实决策已经形成时才创建对应文件。

## 布局

```text
/
├── GLOSSARY-MAP.md
├── docs/agents/GLOSSARY.md
└── knowledge/<topic>/
    ├── GLOSSARY.md            # 按需创建
    └── docs/adr/              # 按需创建
```

`GLOSSARY.md` 只定义领域术语和边界，不记录实现步骤。ADR 只用于难以逆转、缺少背景会令人意外且经过真实取舍的决策。

Issue 标题、分析假设、变更建议等输出使用相关 `GLOSSARY.md` 中的规范术语。确有缺失的术语时，在讨论中澄清并按需记录；仅需读取术语时无需启动建模流程。

如果新结论与现有术语或 ADR 冲突，明确指出冲突并保留原文，不静默覆盖。
